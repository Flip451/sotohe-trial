# 最小認証 API の空パスワード拒否

## Context

パスワードのハッシュ保存に関する既存の決定だけでは、登録とログインの要求で提示されたパスワードが空である場合の扱いは定まらない。利用者に渡る前のアプリケーション境界でこの入力を一貫して扱う判断が必要になった。

## Decision

### D1: アプリケーション境界での空パスワード拒否

登録およびログインは、アプリケーション境界で提示されたパスワードが空である要求を拒否する。

この決定は空文字の入力を対象とし、パスワードのハッシュ方式、保存方法、HTTP の具体的な応答表現は定めない。

## Rejected Alternatives

- 空パスワードを受け入れる: 認証に用いる資格情報として有効なパスワード入力の境界が不明確になるため。
- 登録とログインで異なる境界規則を設ける: 同じ資格情報入力に対する利用者の期待が一致しなくなるため。

## Consequences

- 正: 登録とログインは空のパスワード入力を同じ境界で拒否できる。
- 中立: 空でないパスワードの形式や長さの規則は、この決定では定めない。

## Reassess When

- パスワード以外の認証資格情報を受け付ける必要が生じたとき。
- 空文字を有効な資格情報として扱う外部認証方式との互換性が必要になったとき。
